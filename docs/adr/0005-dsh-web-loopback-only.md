# ADR-005 `dsh web` 只绑 `127.0.0.1`，绝不开公网

**状态**：Accepted（2026-09-20 随初版 `13734e3` 落地；2026-10-07 补记为 ADR）。

**背景**：`dsh web` 的界面等于这台机器的完全控制权（任意命令、任意文件）。
它自己默认只绑回环，而且会拒绝绑 `0.0.0.0`。

**决策**：**不改 `dsh web` 的监听**。`dsh-remote serve` 起它时也不传 `--host`：

```
dsh web --no-open --port <local_port>
```

对外入口**只有**云上的 Caddy 一条（ADR-001）。

**理由**：

- 把界面绑到 `0.0.0.0` 就是把 RCE 挂到公网 —— 用户级规则里这是明确禁区
  （`~/.dsh/AGENTS.md` §5："不要把 `dsh web` 的端口暴露到 `0.0.0.0`（它自己也会拒绝），
  也不要给 Caddy 之外的任何东西开公网入口 —— 那个界面等于这台机器的完全控制权"）。
- 远程访问需要的三件事（隧道、TLS、认证）都由 Caddy + ssh 提供，harness 这边零改动，
  也就不用重启它（ADR-008）。

**判据**：

```sh
ss -ltn | grep ':3080'      # 想看到 127.0.0.1:3080，不是 0.0.0.0:3080
```

云上安全组的判据同理：只放 22（限家里出口 IP）+ 443/8443；
**18080（隧道口）和 3080（harness）永远不放**。

**否决**：

- 让 harness 监听 `0.0.0.0` 再靠防火墙 —— 多一层可失手的墙，且违背用户的硬规矩；
- 给 `dsh web` 传 `--trusted-host` 让它接受域名请求 —— 那要重启 harness，见 ADR-008；
- 在云上再跑一个 harness（会话和文件都不在云上，没有意义）；
- 用 `dsh-remote serve` 之外的方式起 harness（会不会带上别的主机绑定参数不可控）。
